My agentic coding workflow

How I build with AI agents every day: Claude writes the code, I write the rules once and make the decisions.

Davit Khaburdzania23 Oct 20264 min read

I build with AI agents every day, and my agentic coding workflow is pretty simple. I write down what I want and how things should be done, Claude does the work, and I make the decisions.

When I redesigned this site, it took two days. Claude wrote all the code, including a small game called Shiba Land. I reviewed what it made and said what to keep.

One project per product

Each of my products has its own Claude Project: this site, Rillow, Bundle and Unposed. I tell the project what I need, and it starts a separate thread for each task, so several things get done at the same time. I just check what's finished and what needs me, on my laptop or my phone.

Boris Cherny, who made Claude Code, used to juggle ten or more sessions by hand (VentureBeat). A project does that for me. I wrote more about it in how I use Claude Projects.

I write the rules down once

Every project has a short paragraph of instructions, and the code has an AGENTS.md file that explains how the site is built and what the design rules are. Most of those rules are there because I said no to something once, like "never use green". When I correct Claude, I tell it to remember, so I never have to say it twice.

Mitchell Hashimoto calls this engineering the harness: when an agent makes a mistake, you fix its instructions so it doesn't happen again (My AI Adoption Journey).

Claude writes the code, I make the calls

Agents are great at building things. What they can't do is tell which version feels right. Most of my replies are a couple of words, like "too colourful", "i love it" or "Pixel is better".

That's most of my job now. Simon Willison says writing code is cheap now, and when trying three versions takes a few minutes, picking the right one is the work.

My setup

Claude can only use what it can reach, so I connect my tools: GitHub for code, Rillow (my SEO product) for keyword research and briefs, and my Mac through Remote Control for things that only run there, like the design app Paper and the iOS simulator.

This post was made the same way. Claude researched the topic, got a brief from Rillow and wrote a draft. I told it the draft sounded like a computer wrote it, so we rewrote it.

What I keep for myself

I decide what to build, and I approve anything that can't be undone. On this site every push goes live, so I always see a preview first. Anything with my name on it, I check myself.

What still goes wrong

Instructions can be wrong. My first project setup got the branch wrong, and Claude caught it by reading the code. It's also bad at drawing from scratch: the first Shiba drawings came out silly. It works much better with clear rules, like pixel art, or with a design I've already made. And long threads get slow and expensive, so I start a new thread for new work.

If you want to try this

Pick one side project and make it a Claude Project. Write a short paragraph on where the code is, how to check changes and what needs your OK. Ask for a preview before anything ships, keep your answers short, and when you correct Claude, tell it to remember.
