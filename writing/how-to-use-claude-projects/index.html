How to use Claude Projects the right way

How to set up and use the new Claude Projects: instructions, memory, threads and keeping usage down, with examples from my own site.

Davit Khaburdzania23 Oct 20265 min read

If you want to know how to use Claude Projects well, think of a project as one ongoing piece of work. You set it up once and then keep sending it tasks. I run this site, davit.cc, in a project, so the examples here are from my own setup.

What a project is now

Anthropic redesigned Projects in September 2026. A project used to be a folder of files and chats. Now it's a chat with a coordinator that starts a separate thread for each task, and each thread is a full Claude Code session with its own copy of your code. Threads share a memory and report back when they're done.

Projects are in beta on the Pro and Max plans and work in the web, desktop and mobile apps (docs). A lot of guides online still describe the old version.

When to make one

Make a project when the work keeps going: a product, a website, a long migration. For a single task, a normal session is enough. My site is the ongoing kind. The redesign, a new favicon, a few small experiments and this blog all happened in the same project.

Let Claude set it up

I didn't write my setup myself. My first message in the new project was:

Help me set up this new project from my recent work. Look through my recent sessions and repositories, identify the main thread of work, and propose a project setup: a short name, the repositories it should include, an environment, concise project instructions drawn from what kept coming up, and one or two optional routines. Show me the proposal before changing anything.

Claude came back with a name, instructions and a weekly check of the live site, and I said yes.

Keep the instructions short

Project instructions are the rules every thread reads first. Keep them short: where the code is, how to check changes and what needs your OK. Mine are one paragraph:

Site is davit.cc, built from the main branch of davit-khaburdzania.github.io and served by a Cloudflare Worker (wrangler.jsonc). Davit is the only one working on the site, so don't open pull requests: commit and push straight to main. Every push to main deploys davit.cc automatically within about a minute (Cloudflare's GitHub connection), so a push is a production change: show Davit a preview of visual changes before pushing. Keep profile details (location "Tbilisi, Georgia", website davit.cc) consistent across the site, GitHub and LinkedIn. Verify changes on the live site after each push.

The first version got the branch wrong, and the first thread fixed it after reading the code. Rules get added as you go. "No pull requests" came a day later, when I said I'm the only one working on the site.

Instructions, memory and CLAUDE.md

A project keeps context in three places:

Where What goes in it Example from davit.cc
Project instructions Rules every thread needs from the start Push straight to main, and show a preview first
Project memory Decisions Claude picks up as you work The favicon uses the pixel-art Shiba
CLAUDE.md or AGENTS.md in the repo How the code is built and styled "Never use green accents."

Memory fills up when you ask, like "remember that Unposed goes last in the Projects list". If you only write one of the three, make it the file in your repo, because every session reads it, in a project or not.

Send work and walk away

Talk to the coordinator like a colleague. Questions get answered right away, and new work becomes a thread. When a thread needs a decision, it asks with a few options and a recommendation, and you pick one. You can also tell it how you like to work, like "ask before starting new threads".

One thing isn't obvious: when a thread needs your approval, you answer inside that thread. Saying "go ahead" to the coordinator doesn't reach it.

Run work on your own computer

Some work needs your own machine. For me that's Paper, a design app that only runs on my Mac. A project can run that one thread on your computer through Remote Control while the rest stays in the cloud. Turn it on in the desktop app under Settings > Claude Code, then pick "Work locally" in the project chat.

Keep usage under control

Projects use your plan faster than a single chat, because every thread is a full session and several can run at once. You can switch to cheaper models in the project settings. Long threads get expensive too, so start a fresh thread for new work and close the ones you're done with.

Frequently asked questions

When should I use a project instead of a chat?

When the work keeps going, like a product or a site you keep improving. A quick question is fine in a chat.

What's the difference between Claude Projects and Claude Code?

Projects are built on Claude Code. Every thread is a Claude Code session, and the project adds the coordinator, shared instructions and memory.

Can I share a Claude Project with my team?

Not yet. During the beta a project belongs to one person.

Do cloud threads get my local skills and MCP servers?

No. Cloud threads get the connectors and skills from your claude.ai account and whatever is in your repo. Anything installed only on your laptop needs a thread running on your computer.
